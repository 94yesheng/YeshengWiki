# 照片墙数据

照片页的每一段就是一个文件，放在这个目录下。加一面墙 = 加一个文件；删一面墙 = 删一个文件。

## 文件格式

```json
{
  "title": "重庆之行",
  "date": "2024-07-17",
  "place": "重庆 · 洪崖洞",
  "note": "记录文字，会显示在照片页上。",
  "photos": [
    { "file": "2024-07-17-洪崖洞.jpg", "caption": "这里写这一张单独的说明，可留空" }
  ]
}
```

| 字段 | 必填 | 说明 |
|---|---|---|
| `title` | ✅ | 这面墙的标题 |
| `date` | | 必须是 `2024-07-17` 这种格式。**留空则这面墙排在时间轴最后**（归入"未标注时间"） |
| `place` | | 地点，自由文本，可留空 |
| `note` | | 记录文字，可留空。显示在标题下方 |
| `photos[].file` | ✅ | **图片文件名**，图片要放在 `src/assets/photos/` 下，只写文件名不写路径 |
| `photos[].caption` | | 这一张单独的说明，可留空 |

## 几个约定

- **文件名（这个 .json 的名字）决定墙的 id**，用英文小写加连字符，如 `chongqing-2024.json`。
  id 不进网址（照片页没有详情页），但会出现在构建日志和文件列表里，所以起得有意义一点。
- **一面墙可以只有一张照片**，也可以有很多张 —— 这是"照片墙"的本意。
- **图片放 `src/assets/photos/`**，构建时由 Astro 自动压成多尺寸 WebP，不用手工处理。
- **入库前把长边压到 2560px**（约 300–600KB）。道理：照片页上有图最宽也就 1100px 左右，
  2560 已经留了 2 倍余量（视网膜屏），而手机原图一张 2–6MB，几十张就能让仓库胀到几百 MB，
  clone 和构建都会变慢。原图自己留在硬盘上。过渡手段见 `.work/import-photos.mjs`，
  以后由网页后台的上传功能负责。
- 引用了不存在的图片，构建时会打一条警告并跳过那张，不会让整个构建失败。

## 给人工编辑的建议

- 直接改这个目录下的 json 也行；用后台（`/admin/`）改也可以。
- 图片文件名建议保留日期前缀（如 `2026-03-09-鸡煲.jpg`）—— 文件名已经**不承载语义**了（元数据都在 json 里），但带日期在文件夹里排序看着清楚。
